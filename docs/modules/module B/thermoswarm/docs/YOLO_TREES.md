# YOLO для ёлок: обычные, заражённые и нагреватели

Цель — файл `models/rgb.pt` с тремя классами:

| Класс (точно так, латиницей) | Что это |
|---|---|
| `tree` | ёлка без видимых белых отметин |
| `tree_infected` | ёлка, на которой **в этом кадре** видна хотя бы одна белая отметина |
| `heater` | керамический нагреватель (других команд) — включённый или нет |

Зачем нужен `heater`. Нагреватель горячий, тепловизор найдёт его как аномалию — это правильно, он остаётся на карте как тепловая аномалия. Но если он стоит рядом с ёлкой, без YOLO ёлка оказалась бы «заражённой». Когда YOLO на осмотре называет пятно `heater`, сервер **не** заражает им ёлку и пишет в журнал «тёплое пятно рядом — heater, не заражение» (настройка `trees.not_tree_classes`).

Как сервер использует модель:

| Что на поле | Тепловизор | Осмотр T2/T3 (YOLO) | Итог |
|---|---|---|---|
| ёлка с нагретыми отметинами | аномалия A… | `tree_infected` | ёлка E… **заражена** (A…) |
| обычная ёлка | — | `tree` (1 снимок сверху) | ёлка E… **здорова** |
| нагреватель | аномалия A… | `heater` | аномалия A… «heater», ёлки не трогает |
| ёлка с отметинами, тепло не нашлось | — | `tree_infected` | ёлка **заражена (YOLO)** |

Если хотя бы один ракурс из пяти уверенно видит `tree_infected`, итог осмотра — `tree_infected`, даже если с остальных сторон отметин не видно (`yolo.priority_classes`).

## 1. Какие кадры нужны

Модель работает на **фото осмотра**: камера T2/T3 смотрит вниз, высота съёмки `inspect.photo_alt_m` = **2,1 м**, пять точек — над целью и четыре по кругу r = 0,5 м. Цель на этих фото то в центре, то сбоку, иногда обрезана краем. Датасет должен быть таким же.

Сколько:
- **≥ 150 кадров** всего;
- в них **≥ 200 рамок `tree`, ≥ 200 `tree_infected`, ≥ 100 `heater`** (на одном кадре часто несколько объектов);
- **10–15 кадров без этих объектов** (пустой пол, метки, провода, тени) — их не размечают, это «отрицательные» примеры.

### 1.1 Уже готовые кадры — из записей полётов
Каждый полёт сам набирает датасет: на каждую аномалию — 5 фото, на каждую здоровую ёлку — 1. Копируем все фото, кроме размеченных сервером (`*_det.jpg`):
```bash
cd ~/thermoswarm
mkdir -p dataset/raw
cp runs/*/photos/*.jpg dataset/raw/
rm -f dataset/raw/*_det.jpg
ls dataset/raw | wc -l
```

### 1.2 Досъёмка в ручном режиме (15–20 минут)
1. Сервер запущен, на поле ёлки (обычные и с отметинами) и нагреватели.
2. Панель «Ручное управление»: дрон **T2**, высота **2.1**, «Взлёт».
3. «клик по карте = лететь» → над ёлкой → кнопка **📷** в карточке T2. Затем точки в 0,5 м восточнее, севернее, западнее, южнее — снова 📷 в каждой. Кадры сохраняются в `dataset/raw/`.
4. Так же — над каждым нагревателем и над местами, где ёлка и нагреватель стоят рядом (это самое важное для различения).
5. Между заходами **поверните ёлки** (отметины в другую сторону) и переставьте нагреватели. Снимите немного кадров с высоты 1,8 и 2,4 м — модель станет устойчивее.
6. «Сесть». Если есть T3 — его камера тоже годится, кадры одинаковые.

## 2. Разметка

### Правила (важно для качества)
- **Рамка — вокруг всей кроны** ёлки, включая кончики веток. Не вокруг отметины.
- `tree_infected` — **только если отметина видна в этом кадре**. Если ёлка заражена, но в этом кадре отметины не видно (с другой стороны) — размечаем `tree`. Модель может выучить только то, что видно; итог по пяти ракурсам сервер сделает сам.
- Объект обрезан краем кадра — размечать, если видно больше ~30 % его. Меньше — не размечать.
- `heater` — корпус нагревателя целиком (с подставкой), включён он или нет.
- **Не** размечать: тени ёлок, метки ArUco, провода, лист фанеры, наши дроны (или размечайте их как `drone` — сервер этот класс игнорирует).
- Имена классов — ровно `tree`, `tree_infected`, `heater`, строчными.

### Вариант A: Roboflow (проще всего, в браузере)
1. roboflow.com → Create New Project → **Object Detection**, имя `thermoswarm-trees`.
2. Upload → перетащить папку `dataset/raw` → Save and Continue.
3. Annotate → классы `tree`, `tree_infected`, `heater` → разметить все кадры (клавиша B — рамка, стрелки — следующий кадр). Пустые кадры отметить «Mark Null».
4. Add to Dataset → разбиение можно оставить любое (мы перемешаем сами).
5. **Generate** → Preprocessing: Auto-Orient — **вкл**, Resize — **выкл** (или Fit within 640×640). Augmentation — **никаких** (их делает обучение).
6. **Export Dataset** → Format **YOLOv8** → Download zip → распаковать, например, в `~/trees_export`.

### Вариант B: Label Studio (локально)
`pip install label-studio && label-studio` → новый проект → Object Detection with Bounding Boxes → три класса → импорт `dataset/raw` → разметка → Export → **YOLO** → распаковать в `~/trees_export` (там будут `images/`, `labels/`, `classes.txt`).

## 3. Обучение

### 3.1 Перемешать и разбить (80 % обучение / 20 % проверка)
```bash
cd ~/thermoswarm
source .venv/bin/activate
python tools/yolo.py split --src ~/trees_export --out dataset/yolo_trees
```
Скрипт напечатает число рамок по классам — сверьте с п. 1 (≥ 200 / 200 / 100).

### 3.2a На ноутбуке с видеокартой NVIDIA
```bash
pip install ultralytics
python tools/yolo.py train --data dataset/yolo_trees/data.yaml --epochs 150
```
Готовые веса сами лягут в `models/rgb.pt`, в конце будет строка `val mAP50=…`. Без видеокарты добавьте `--device cpu` (на ~150 кадрах это 1–3 часа).

### 3.2b В Google Colab (бесплатная видеокарта)
1. Заархивировать: `cd dataset && zip -r yolo_trees.zip yolo_trees`.
2. colab.research.google.com → Новый блокнот → Среда выполнения → Сменить тип → **T4 GPU**.
3. Ячейки:
```python
!pip -q install ultralytics
from google.colab import files
files.upload()                      # выбрать yolo_trees.zip
!unzip -q yolo_trees.zip
!sed -i "s#^path:.*#path: /content/yolo_trees#" yolo_trees/data.yaml
!yolo detect train data=yolo_trees/data.yaml model=yolo11n.pt imgsz=640 epochs=150 patience=40 degrees=10 flipud=0.5 fliplr=0.5
files.download('runs/detect/train/weights/best.pt')
```
4. Скачанный `best.pt` положить как `~/thermoswarm/models/rgb.pt`.

Повороты и отражения при обучении включены специально: камера смотрит вниз, ёлка под любым углом — та же ёлка.

## 4. Проверка качества

1. **Цифры** (в конце обучения или в `runs_yolo/rgb/results.csv`): mAP50 по всем классам **≥ 0,85** — хорошо; 0,7–0,85 — доснять и доразметить; < 0,7 — что-то не так с разметкой.
2. **Путаница классов**: `runs_yolo/rgb/confusion_matrix.png` (в Colab — `runs/detect/train/`). Главное — чтобы `tree` и `tree_infected` не путались. Если путаются — нужно больше кадров, где отметины мелкие или сбоку.
3. **Глазами** на кадрах, которых модель не видела (снимите 10–20 новых):
```bash
python tools/yolo.py test --weights models/rgb.pt --src dataset/raw_new
```
Картинки с рамками — в `runs_yolo/test/`. Смотрите: нагреватель ни разу не назван ёлкой, ёлка с видимой отметиной — `tree_infected`.

## 5. Подключение

1. `models/rgb.pt` на месте; на ноутбуке-сервере стоит `ultralytics` (один раз: `source .venv/bin/activate && pip install -r requirements-nn.txt`) → перезапустить сервер (`./start_server.sh`).
2. В шапке таблицы аномалий вместо «YOLO не загружен» — `YOLO rgb.pt (tree, tree_infected, heater)`.
3. Настройки в `config.json` (уже стоят):
```json
"yolo":  { "weights": "models/rgb.pt", "conf": 0.35, "priority_classes": ["tree_infected"], "ignore_classes": ["drone"] },
"trees": { "not_tree_classes": ["heater"] }
```
Если нагреватели в итоге названы иначе (например, `heater_ceramic`) — впишите это имя в `not_tree_classes`.
4. Полёт: в журнале у осмотров появятся «… ракурс «север» — tree_infected 87%», в конце — «итог по 5 ракурсам — tree_infected (2 из 5)», в таблице «Ёлки» — заражённые/здоровые.

После каждого полёта новые фото из `runs/*/photos/` можно добавлять в датасет и дообучать (п. 1.1 → 2 → 3): модель становится лучше на вашем полигоне и освещении.

## 6. Частые ошибки

| Что видно | Причина | Что делать |
|---|---|---|
| Всё «не распознано» | порог `yolo.conf` высок или модель не та | `tools/yolo.py test` на тех же фото; `conf` 0.25 |
| Нагреватель назван `tree` | мало кадров нагревателей рядом с ёлками | доснять п. 1.2 (4), доразметить |
| Заражённая ёлка → `tree` | отметины видны только с одной стороны, модель их не уверенно видит | больше кадров с отметинами сбоку и мелко; проверить, что отметины не размечены как `tree` |
| Ёлка обведена не целиком | разметка рамкой по отметине | переразметить: рамка вокруг всей кроны |
| `split`: «classes.txt not found» | экспорт не в формате YOLO | Roboflow → YOLOv8, Label Studio → YOLO |

Дополнительно (не обязательно): та же схема, но с кадров T1 **с высоты 3 м во время облёта** → `models/trees.pt` и `"trees": {"detector": "yolo"}` — тогда и карта ёлок будет строиться нейросетью вместо детектора «тёмные колючие кроны». Сейчас этот детектор работает без обучения.

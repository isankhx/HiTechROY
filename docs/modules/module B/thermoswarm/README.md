# ThermoSwarm — рой из трёх «Техников»: тепловой облёт + фото аномалий + YOLO

**Пошаговый запуск на площадке — [LAUNCH.md](LAUNCH.md).**

Ставите три дрона на поле, нажимаете **«Старт роя»**. Дальше всё происходит само:

1. Все три взлетают (с интервалом 2 с) и находят себя по ArUco-меткам (карта `aruco_map.txt`: 45 меток ID 100–144, 25 см, шаг 75 см, начало в центре №122).
2. **T1 (тепловизор)** облетает поле «змейкой» на 2 м. Галсы рассчитываются по углу обзора тепловизора. T1 ищет места, которые теплее фона (ΔT ≥ 3 °C), и ставит их на карту.
3. Аномалия подтверждается, когда её видели минимум на 2 кадрах и T1 пролетел мимо (координата уже уточнена). Ближайший свободный **T2/T3** облетает участок: снимок сверху с 1 м и четыре ракурса по кругу r = 0,5 м. Сервер прогоняет снимки через **YOLO** и сводит итог по ракурсам («fire, 5 из 5»). Если YOLO ничего не нашёл, тепловая аномалия всё равно остаётся. Если фотодронов нет или оба выбыли, осмотры после облёта делает сам T1.
4. Все дроны знают позиции друг друга. Между корпусами держится **зазор ≥ 0.5 м**: центры не ближе 2·0,28 + 0,5 + 0,2 запаса на ошибку позиции = 1,26 м (сервер); борт сам останавливается, если сосед ближе 1,06 м. Пролёт одного дрона над другим запрещён. Мешающий дрон отходит в сторону, низший по приоритету уступает дорогу.
5. После облёта T1 садится на место старта. T2/T3 садятся на свои места, когда закончат осмотры.

В браузере видно карту с метками, тепловую карту, позиции, маршруты и следы дронов, зону зазора вокруг каждого, видео со всех трёх камер, живой тепловой кадр, таблицу аномалий и журнал. Клик по аномалии открывает тепловой кадр, фото, найденные объекты, координаты ±погрешность и время.

```
 ноутбук на площадке (сервер + браузер)          «Техник» × 3 (Orange Pi, ROS, PX4)
 ┌────────────────────────────────────┐   Wi-Fi  ┌───────────────────────────────┐
 │ run_server.py  :8080 веб-интерфейс │◄────────►│ board/agent.py                │
 │  · миссия, разведение дронов       │ TCP 7700 │  · /navigate /land            │
 │  · тепловая карта, аномалии        │          │  · /get_telemetry (aruco_map) │
 │  · YOLO по фото                    │          │  · камера, тепловизор (USB)   │
 └────────────────────────────────────┘          │  · свой сторож связи/дистанции│
                                                 └───────────────────────────────┘
```

## 1. Попробовать в симуляции (5 минут, без дронов)

Нужен Python 3.10+ (Windows / Linux / macOS).

```bash
cd thermoswarm
python -m venv .venv
# Windows: .venv\Scripts\activate      Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python run_server.py --sim             # --speed 3 = ускорить в 3 раза
```

Откройте http://127.0.0.1:8080 и нажмите «Старт роя». Виртуальные дроны подключаются к серверу по тому же протоколу, что и настоящие. В симуляции порт для бортов открыт только на 127.0.0.1, поэтому настоящий дрон к такому серверу не подключится. Без весов YOLO в симуляции работает цветовой SIM-детектор: он помечен в интерфейсе и понимает только нарисованные объекты.

## 2. Ноутбук-сервер на площадке

1. Установка такая же, как в п. 1. Для YOLO дополнительно: `pip install ultralytics`, а веса положите в `models/rgb.pt` (см. п. 6).
2. Ноутбук и три Orange Pi должны быть в одной Wi-Fi сети. Узнайте IP ноутбука (`ipconfig` / `ip a`).
3. Разрешите входящий TCP-порт **7700** (на Windows брандмауэр спросит при первом запуске, разрешите для частной сети).
4. Запуск: `./start_server.sh` (Linux: сам создаст `.venv` и поставит зависимости — на Ubuntu 24.04 `pip install` вне окружения запрещён) или `python run_server.py` из активированного окружения. Интерфейс: http://127.0.0.1:8080. Чтобы открыть его с телефона или планшета: `python run_server.py --http-host 0.0.0.0`, затем http://IP-ноутбука:8080.

## 3. Каждый «Техник»

Быстрее всего — скриптом с ноутбука (Linux/macOS/WSL/Git Bash), по одному разу на борт:

```bash
./tools/deploy_board.sh T1 orangepi@<IP-T1> <IP-ноутбука> tr256i   # или ssh-алиас: technic-1
./tools/deploy_board.sh T2 orangepi@<IP-T2> <IP-ноутбука>
./tools/deploy_board.sh T3 orangepi@<IP-T3> <IP-ноутбука>
```
Вторым аргументом — всё, что понимает `ssh`: `user@ip` или алиас из `~/.ssh/config`. Пользователь и домашняя папка на борту определяются автоматически. Чтобы пароль не спрашивали много раз: `ssh-copy-id <цель>`.

Скрипт копирует агент, пишет `agent.json`, делает самопроверку (`--check`, без арминга), проверяет тепловизор и ставит автозапуск. Вручную — так:

Скопируйте папку `board/` на Orange Pi:

```bash
scp -r board orangepi@<IP-дрона>:~/thermoswarm
ssh orangepi@<IP-дрона>
cd ~/thermoswarm && cp agent.example.json agent.json && nano agent.json
```

В `agent.json` поменяйте:

| поле | T1 (тепловизор) | T2 | T3 |
|---|---|---|---|
| `id` | `"T1"` | `"T2"` | `"T3"` |
| `server` | IP ноутбука | IP ноутбука | IP ноутбука |
| `thermal.driver` | см. п. 4 | `"none"` | `"none"` |

**Карта меток на борту.** Штатный узел `aruco_map` должен использовать ту же карту, что и сервер: `board/aruco_map.txt`, это тот же файл. Положите её туда, куда указывает launch-файл ArUco вашего «Техника» (обычно `~/technic_ws/src/technic/aruco_pose/map/`), и проверьте словарь детектора: в файле карты указан `DICT_4X4_1000`. Для этого откройте launch-файл: `grep -rn "map\|dictionary" ~/technic_ws/src/technic/*/launch/*aruco*`.

Самопроверка (дрон не армится, пропеллеры лучше снять):

```bash
source ~/technic_ws/devel/setup.bash
python3 agent.py --check
```

Самопроверка выводит телеметрию в `aruco_map`, возраст позиции по карте, число видимых меток, наличие кадров камеры и доступность сервера. Если камера опубликована под другим топиком, найдите его (`rostopic list | grep compressed`) и впишите в `camera_topic`.

Ручной запуск агента: `python3 agent.py`. После него в карточке дрона в браузере появится «связь». Автозапуск при включении дрона:

```bash
sudo cp thermoswarm-agent.service /etc/systemd/system/
sudo systemctl enable --now thermoswarm-agent     # логи: journalctl -u thermoswarm-agent -f
```

Не запускайте одновременно Technic Show или другие скрипты, которые вызывают `/navigate`: у каждого дрона должен быть один источник команд. Второй экземпляр агента на том же борту не запустится сам.

## 4. Тепловизор Mileseey TR256i (USB-C)

На T1 стоит **Mileseey TR256i**: 256×192 пикселя, 25 Гц, поле зрения 56°×42°, −15…600 °C, разъём USB-C. Производитель заявляет работу с Android; на Linux (Orange Pi) такие камеры обычно видны как UVC-устройство с кадром YUYV 256×384: верхняя половина — изображение, нижняя — температура в единицах K×64. **Это нужно проверить на вашем экземпляре** (шаги ниже).

1. Подключите камеру к USB Orange Pi через переходник USB-A → USB-C.
2. `lsusb` — должно появиться новое устройство; `v4l2-ctl --list-devices` — новое `/dev/videoN`.
3. В `agent.json` на T1:
   ```json
   "thermal": {"driver": "tr256i", "device": "auto", "width": 256, "height": 192, "bin": 2, "fps": 8}
   ```
   `device: auto` — агент сам найдёт камеру среди `/dev/video*` (основная камера «Техника» занята ROS и пропускается). `bin: 2` — прореживание 2×2 на борту (128×96, ≈3 Мбит/с по Wi-Fi вместо 12,6).
4. Проверка без ROS и полёта:
   ```bash
   python3 agent.py --probe-thermal
   ```
   Печатает `lsusb`, форматы всех видеоустройств, выбранное устройство, размер кадра, минимум/медиану/максимум и частоту; последний кадр — в `thermal_probe.csv`. Ожидается строка `256x384 YUYV, temperature half` и температуры около комнатной; рука перед камерой повышает максимум.
   - Если камера отдаёт только изображение 256×192 (без температурной половины), драйвер перейдёт на уровни яркости (`units raw`) — обнаружение работает по разнице с фоном, порог `threshold` подберите по `--probe-thermal`.
   - Если камера не определяется как видеоустройство вовсе — запасной вариант: GY-MCU90640 по USB-UART, `"driver": "mlx_serial"`, в `config.json` поле зрения 55×35.

Другие поддерживаемые драйверы: `mlx_serial` (GY-MCU90640/MLX90640, поток `5A 5A`), `serial_csv` (Arduino/ESP32, строка чисел), `uvc` (любая UVC-камера, уровни яркости), `uvc_split16` (то же, что `tr256i`).

**Ориентация и угол обзора** задаются в `config.json` на ноутбуке, в разделе `thermal`:

- `hfov_deg`, `vfov_deg` — углы обзора по ширине и высоте кадра (TR256i: 56 и 42). От них зависят шаг галсов (при 2 м: полоса 2,13 м, шаг 1,49 м, 3 галса) и точность координат.
- `rotate_deg` (0/90/180/270), `flip_h`, `flip_v`. Проверка: включите агент, поверните дрон носом вдоль оси +X поля (красная стрелка на карте у метки 122) и поднесите тёплую руку спереди от дрона. На живом тепловом кадре в браузере рука должна появиться **сверху**. Рука слева от дрона — **слева** на кадре. Если не так, поменяйте `rotate_deg` или `flip_*` и перезапустите сервер.
- `threshold` — на сколько градусов (или единиц для `uvc`) теплее фона считается аномалией.
- `target_height_m` — ожидаемая высота нагретых объектов. Координаты и высоту аномалий сервер находит сам триангуляцией по лучам из разных точек облёта (колонка «h, м»), а этот параметр задаёт плоскость тепловой подложки на карте. Поставьте его близко к реальной высоте источников: тогда подложка не будет «размазана».

Финальная проверка: поставьте кружку с горячей водой на метку 122 и запустите миссию. Аномалия должна появиться около (0; 0).

## 5. Полёт

- Поставьте дроны **не ближе 1.2 м друг от друга** (центры), лучше на метки. Например, T1 на 104, T2 на 101, T3 на 107.
- Нажмите «Старт роя». Если дрон после взлёта не увидел метки за 15 с, он садится, а остальные продолжают. Если не нашёл себя T1, садятся все.
- **Пульт главнее программы.** Если пилот переключил режим на пульте, агент перестаёт отправлять этому дрону команды до посадки, а миссия продолжается без него.
- **Пауза** — все зависают на месте. **Домой и посадка** — все возвращаются на места старта. **ПОСАДИТЬ ВСЕХ** — немедленная посадка на месте. «Посадить» в карточке сажает один дрон.
- Нет связи с ноутбуком 1.5 с — борт сам зависает, 6 с — садится. Сосед ближе зазора и дрон летит к нему — борт сам останавливается.
- Метки не видны 2 с — дрон зависает и ждёт; увидел снова — продолжает; не видны 10 с — садится (`localization` в `config.json`). Борт отклонил команду (не OFFBOARD, не видит карту) — это видно в журнале, сервер ждёт секунду и строит следующий шаг от реального положения.
- Севший или перехваченный пультом дрон становится препятствием: остальные его облетают, галс рядом с ним укорачивается, точка съёмки сдвигается от него на безопасное расстояние.
- Аномалия попадает в очередь осмотра после того, как T1 пролетел над ней (положение уже уточнено). Если координата уточнилась, пока T2/T3 летит, цель обновляется.
- Для взлёта по `navigate(frame_id=body, auto_arm=True)` PX4 нужна позиция **до** того, как камера увидит метки: оптический поток с дальномером или метка под камерой на земле. Если на вашем «Технике» штатный взлёт так не работает, сначала проверьте его одним дроном с пульта наготове.

Порядок первых полётов: `--check` без пропеллеров, затем один T1 (отключите T2 и T3, тогда миссия пойдёт без них), затем пара, затем трое.

## 6. YOLO: как обучить на ваши объекты

Модель распознаёт объекты на фото, которые T2/T3 делают с высоты `inspect.photo_alt_m` (по умолчанию 1 м). Снимать датасет нужно так же: сверху, этой же камерой, с той же высоты.

1. **Сбор.** Разложите объекты на поле, поднимите T2 вручную на ~1 м и жмите 📷 в карточке дрона. Кадры сохраняются в `dataset/raw/`. Нужно ≥100–200 снимков на класс: разные положения, повороты, освещение, плюс кадры без объектов.
   Если в `--check` камера 320×240, поднимите разрешение камеры в launch-файле «Техника» до 640×480: YOLO станет точнее, а ArUco немного медленнее.
2. **Разметка.** [Label Studio](https://labelstud.io) (`pip install label-studio && label-studio`), CVAT или Roboflow. Рамки вокруг объектов, экспорт в формате **YOLO**.
3. **Разбивка:** `python tools/yolo.py split --src <папка экспорта> --out dataset/yolo`
4. **Обучение.** На ноутбуке с NVIDIA GPU:
   `pip install ultralytics && python tools/yolo.py train --data dataset/yolo/data.yaml`.
   Без GPU используйте Google Colab: загрузите `dataset/yolo`, выполните `!pip install ultralytics` и `!yolo detect train data=data.yaml model=yolo11n.pt imgsz=640 epochs=100`, затем скачайте `runs/detect/train/weights/best.pt`.
5. Положите веса в **`models/rgb.pt`** и перезапустите сервер. В шапке таблицы аномалий появится `YOLO rgb.pt (ваши классы)`. Проверка на фото: `python tools/yolo.py test --src dataset/raw`.

Названия классов берутся из весов, менять код не нужно. Распознавание идёт на ноутбуке: одно фото на CPU обрабатывается примерно за 0.1–0.5 с, а не в реальном времени.

**Ёлки и нагреватели — пошаговый гайд: [docs/YOLO_TREES.md](docs/YOLO_TREES.md).** Для осмотров удобно размечать два класса: `tree` (обычная ёлка) и `tree_marked` (с белыми отметинами), — в `models/rgb.pt` они попадут в итог осмотра. Карта ёлок во время облёта работает и без обучения (детектор «тёмные колючие кроны»). Если же обучить отдельную модель на кадрах **сверху с высоты облёта T1** (3 м) и положить её в `models/trees.pt` с `"trees": {"detector": "yolo"}`, она заменит этот детектор. Кадры для неё — кнопка 📷 у T1 на высоте 3 м.

### 6.1 ИК-нейросеть (кейс К3-09)

Кроме порога ΔT сервер умеет искать аномалии нейросетью прямо на тепловых кадрах TR256i (классы `thermal_anomaly` и `drone` — горячие моторы соседа). Модель на реальных кадрах **ещё не обучена**; порядок:

1. Слетать T1 над имитациями (обычная миссия) — все сырые тепловые кадры сохраняются в `runs/<дата>/thermal.f32`.
2. `python tools/thermal_dataset.py export --run runs/<дата> --out dataset/thermal_raw` — кадры с предразметкой по порогу; исправить разметку в Label Studio / CVAT.
3. `python tools/yolo.py split --src <экспорт> --out dataset/thermal` и `python tools/yolo.py train --data dataset/thermal/data.yaml --thermal --imgsz 128` → `models/thermal.pt`.
4. В `config.json`: `"detector": "both"` (порог + сеть) или `"nn"`. Детекции сети в полёте пишутся в `runs/<дата>/nn.jsonl`.
5. Зачётная точность по полёту: `python tools/thermal_eval.py flight --run runs/<дата> --labels <разметка кадров этого полёта>` → mAP@0.5 (требование ≥ 0,85).

Проверка конвейера без реальных данных: `python tools/thermal_dataset.py synth` (синтетические кадры геометрии TR256i) и те же шаги 3–4.

## 7. Главные настройки `config.json`

| ключ | что | по умолчанию |
|---|---|---|
| `separation.min_gap_m` | зазор между корпусами | 0.5 |
| `separation.position_margin_m` | запас на ошибку позиции (на пару аппаратов) | 0.2 |
| `separation.drone_radius_m` | радиус дрона с винтами (измерьте!) | 0.28 |
| `thermal.alt_m`, `thermal.speed_mps` | высота и скорость теплового облёта | 2.0 м, 0.3 м/с |
| `thermal.overlap` | перекрытие галсов | 0.3 |
| `inspect.cruise_alt_m`, `photo_alt_m` | высота перелёта и съёмки T2/T3 | 1.3 / 1.0 м |
| `flight.speed_mps` | скорость T2/T3 | 0.4 |
| `flight_bounds` | куда центрам дронов можно залетать | поле −0.15 м |
| `drones[].priority` | кто кому уступает дорогу | T1 > T2 > T3 |
| `inspect.orbit_points`, `orbit_radius_m` | облёт участка: число ракурсов по кругу и радиус | 4, 0.5 |
| `thermal.detector` | `threshold` / `nn` / `both` — пороговая детекция и/или ИК-нейросеть | threshold |

## 8. Записи

Каждый запуск сохраняется в `runs/<дата-время>/`: `events.jsonl` (журнал), `telemetry.jsonl`, `thermal.f32` + `thermal.jsonl` (все сырые тепловые кадры с позой дрона), `photos/`, `anomalies.json`. Кнопка «⤓ Отчёт» скачивает всё это одним zip.

## 9. Отказы и их имитация

Все отказы, реакция на них и способ проверки собраны в [docs/FAILURES.md](docs/FAILURES.md). В симуляции любой отказ можно включить в панели «Отказы (симуляция)» (потеря связи, потеря меток, перехват пультом, низкая батарея, смерть тепловизора/камеры, снос ветром, скачок позиции, отказ взлёта, отказ мотора…) или через `POST /api/sim/fault`. Автотест всех сценариев: `python tests/test_faults.py` (~5 мин), одного: `python tests/test_faults.py link`.

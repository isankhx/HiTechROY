# ThermoSwarm — полный путь запуска и настройки

Порядок: сервер → SSH к бортам → карта меток → тепловизор → агенты на борта → проверки на земле → полёт T1 → пара → тройка.
Команды с `technic-N` выполняются **на сервере** (через ssh), остальные — там, где указано.

Сеть: **сервер `192.168.1.69`** (машина с `run_server.py`), T1 — `192.168.1.100` (`technic-1`), T2 — `technic-2`, T3 — `technic-3` (алиас создаётся в разделе 2). Если адрес сервера сменится — замените `192.168.1.69` во всех командах ниже и повторите раздел 5.

---

## 0. Что должно быть

- 3 × SKYRIS «Техник 6S» со штатным ПО (ROS, сервисы `navigate`, `get_telemetry`, `land`, узлы ArUco), заряженные АКБ.
- На T1 — тепловизор Mileseey TR256i, смотрит вниз, кабель закреплён, переходник USB-C → USB-A в порт Orange Pi.
- Поле с 45 метками ID 100–144 (сетка 9 × 5, шаг 0,75 м, центр — метка 122).
- Сервер (Ubuntu 24.04) в той же Wi-Fi сети `192.168.1.x`, что и три Orange Pi.
- Пилот с пультом на всё время полётов. Пропеллеры снимаются для всех проверок до раздела 7.

## 1. Сервер

### 1.1 Установка / обновление

```bash
cd ~
unzip -o thermoswarm_2026-11-11_final.zip      # распаковка поверх; ~/thermoswarm/.venv сохраняется
cd ~/thermoswarm
chmod +x start_server.sh tools/deploy_board.sh
```

### 1.2 Проверка в симуляции (2 минуты, без дронов)

```bash
./start_server.sh --sim
```

Первый запуск сам создаёт `.venv` и ставит зависимости. Если пишет `python3-venv is missing`, выполните `sudo apt install -y python3-venv` и запустите ещё раз.
Откройте интерфейс (п. 1.4) и нажмите **«Старт роя»**. Три виртуальных дрона взлетят, облетят поле, найдут 4 нагретых объекта и сядут. Затем остановите сервер: **Ctrl+C**.

```bash
sudo ufw allow 7700/tcp          # если включён ufw; проверить: sudo ufw status
hostname -I                      # должен быть 192.168.1.69
./start_server.sh                # реальные дроны; порт для бортов 7700
```

Нормальный вывод:

[..] info Интерфейс оператора: http://127.0.0.1:8080

### 1.4 Интерфейс оператора

- **Браузер на самом сервере:** http://127.0.0.1:8080.
- **Браузер на ноутбуке, сервер без экрана**, — любой из двух способов:
  - туннель с ноутбука: `ssh -L 8080:127.0.0.1:8080 user@192.168.1.69`, затем http://127.0.0.1:8080 на ноутбуке;
  - или запуск сервера с `./start_server.sh --http-host 0.0.0.0`, затем http://192.168.1.69:8080. Так интерфейс доступен всем в этой сети.

## 2. SSH-доступ к бортам

У T1 и T2 алиасы уже есть (`technic-1`, `technic-2`). Для T3 добавьте такой же блок на сервере:

```bash
cat >> ~/.ssh/config <<'EOF'

Host technic-3
    HostName <IP-T3>
    User orangepi
    IdentityFile ~/.ssh/id_ed25519_technic
    IdentitiesOnly yes
    ForwardAgent no
    ServerAliveInterval 1
EOF
ssh-copy-id -i ~/.ssh/id_ed25519_technic.pub technic-3     # один раз, спросит пароль orangepi
```

Как найти `<IP-T3>`:
- `grep -A1 "Host technic-2" ~/.ssh/config` — T3, скорее всего, рядом с адресом T2;
- `ip neigh | grep 192.168.1.` или `nmap -sn 192.168.1.0/24`;
- `hostname -I` на самом борту.

Проверка: все три команды должны ответить **без пароля**.
```bash
ssh technic-1 hostname; ssh technic-2 hostname; ssh technic-3 hostname
```

## 3. Карта меток на бортах

Сервер и все борта должны использовать один и тот же файл карты. Его контрольная сумма начинается с `1fdbc6d9`.

```bash
sha256sum ~/thermoswarm/aruco_map.txt                       # на сервере: 1fdbc6d918801ba3...
for t in technic-1 technic-2 technic-3; do
  echo "== $t"
  ssh $t 'source ~/technic_ws/devel/setup.bash; m=$(rosparam get /aruco_map/map 2>/dev/null); echo "map: $m"; [ -n "$m" ] && sha256sum "$m"; echo "dictionary: $(rosparam get /aruco_detect/dictionary 2>/dev/null)"'
done
```

- Если `rosparam` ничего не вернул, ROS на борту не запущен: включите борт и подождите загрузки.
- **Нужный результат:** у всех трёх `map: …/aruco_pose/map/field.txt` с суммой `1fdbc6d9…` и одинаковый `dictionary`.

**Состояние на 11.11:** T1 — `field.txt`, сумма совпадает. T2 и T3 — `map1.txt` (сумма `2a2515…`, другая карта) → переключить:

```bash
# 1. карта поля + замена map1.txt → field.txt в launch-файлах (копии .bak)
for t in technic-2 technic-3; do
  echo "== $t"
  scp ~/thermoswarm/aruco_map.txt $t:technic_ws/src/technic/aruco_pose/map/field.txt
  ssh $t 'grep -rln "map1.txt" ~/technic_ws/src | grep -v "\.bak$"; for f in $(grep -rln "map1\.txt" ~/technic_ws/src --include="*.launch"); do sed -i.bak "s#map1\.txt#field.txt#g" "$f"; echo "исправлен: $f"; done'
done
# 2. перезагрузка, чтобы ROS перечитал карту
ssh -t technic-2 'sudo reboot'; ssh -t technic-3 'sudo reboot'
# 3. через 1–2 минуты — снова проверка выше
```

Если для борта не появилось ни одной строки «исправлен:», значит `map1.txt` задаётся не в `.launch`, а в файле из вывода `grep` (например `.yaml`): поправьте имя там вручную. Откат: вернуть файлы `*.launch.bak`.

- **Словарь:** на всех бортах `dictionary: 2` = `DICT_4X4_250`. Это совместимо с полем: в файле карты указан `DICT_4X4_1000`, а меньшие словари OpenCV 4×4 совпадают с началом большего, поэтому метки с ID 100–144 одинаковы в обоих. Менять не нужно, главное — одинаковый словарь на всех трёх.

## 4. Тепловизор TR256i на T1

```bash
ssh technic-1 lsusb                     # должно появиться новое устройство (камера)
ssh technic-1 'v4l2-ctl --list-devices' # новое /dev/videoN
```

Если `v4l2-ctl` нет: `ssh -t technic-1 'sudo apt install -y v4l-utils'`. Подробная проверка — в шаге 5: скрипт запустит `--probe-thermal`.

**Проверено на T1 (11.11):** TR256i = `0bda:5840 Realtek … USB Camera`, режимы `YUYV 256x192` и `256x384 @ 25 fps` — правильный режим (картинка + температура).

**Внимание — нумерация камер сдвигается.** Когда TR256i подключён, он может стать `/dev/video0`, а штатная RGB-камера — `/dev/video2`. Если камера «Техника» в launch-файле открывает `/dev/video0`, она захватит тепловизор, и ArUco перестанет работать. Проверка:
```bash
ssh -t technic-1 'sudo fuser -v /dev/video*; ls -l /dev/v4l/by-id/'
ssh technic-1 'grep -rn "/dev/video" ~/technic_ws/src --include=*.launch'
```
Решение — указать в launch-файле камеры «Техника» постоянное имя RGB-камеры из `/dev/v4l/by-id/` (строка `…USB_2.0_Camera…-video-index0`) вместо `/dev/videoN` и перезагрузить борт. Агент находит тепловизор сам по режиму `256x384`, ему номер не важен.

## 5. Агенты на борта

Один раз на каждый борт, **без пропеллеров**, при работающем сервере:

```bash
cd ~/thermoswarm
./tools/deploy_board.sh T1 technic-1 192.168.1.69 tr256i
./tools/deploy_board.sh T2 technic-2 192.168.1.69
./tools/deploy_board.sh T3 technic-3 192.168.1.69
```

Если рабочее пространство ROS не `~/technic_ws`, укажите путь к `setup.bash` пятым аргументом.

Скрипт делает пять шагов:
1. копирует агента в `~/thermoswarm` на борту;
2. пишет `agent.json` (ID, адрес сервера, драйвер тепловизора);
3. запускает **самопроверку `--check`** — 8 секунд, дрон **не армится**;
4. на T1 проверяет тепловизор (`--probe-thermal`);
5. ставит автозапуск `thermoswarm-agent` (здесь может спросить пароль `sudo`).

**Что должно быть в выводе `--check`:**

| Строка | Норма | Если не так |
|---|---|---|
| `ROS services from technic.srv` (или `clover.srv`) | есть | ROS не запущен или другое имя пакета: впишите его в `srv_packages` в `agent.json` |
| `telemetry aruco_map: connected=True ... x=… y=… z=…` | `connected=True`; x, y, z — числа, если камера видит метку; `nan` на земле — норма | `connected=False` — нет связи Orange Pi с PX4 |
| `map pose age` | несколько десятых секунды, если под камерой метка | `NEVER` — метки не видны: поднимите борт рукой над полем и повторите |
| `markers visible` | ≥ 1 над меткой | см. выше |
| `camera: jpeg, … bytes` | есть | `NO FRAMES` — ниже `--check` печатает `image topics published` и `aruco topics published`: если топик камеры другой — впишите его `*/compressed` в `camera_topic`; если `NONE` — камера ROS «Техника» не запущена или открыла не то устройство (раздел 4) |
| `server <IP>:7700 reachable` | есть | неверный IP сервера, ufw, или сервер не запущен |

**Что должно быть в `--probe-thermal` (T1):**
- в списке форматов: `256x384` или `256x192`, YUYV;
- `thermal: 256x384 YUYV, temperature half 256x192 (K*64)` — **лучший случай**, градусы;
- строки `frame N 256x192 min … median … max … C` с медианой около комнатной температуры (15–30 °C). Поднесите руку к объективу — `max` должен вырасти;
- `thermal: no temperature half … grey levels (units raw)` — камера отдаёт только картинку. Работать будет по разнице с фоном; `threshold` в `config.json` подберите по разнице «рука − фон» в выводе;
- `cannot open /dev/videoN — busy: …` — устройство держит другой процесс: `thermoswarm-agent` (остановите службу перед ручной проверкой: `sudo systemctl stop thermoswarm-agent`) или камера ROS «Техника» (раздел 4).
- `thermal camera not found` — камера не определилась как UVC. Попробуйте другой USB-порт или переподключите. Если не помогло — запасной модуль GY-MCU90640 (`driver: mlx_serial`, поле зрения 55×35 в `config.json`).

**После установки** в интерфейсе в карточках T1, T2, T3 должны появиться «связь … мс», режим, АКБ, а в плитках камер — видео.
Логи агента: `ssh technic-1 journalctl -u thermoswarm-agent -f`.
Если агента нужно поправить вручную: `ssh technic-1`, отредактировать `~/thermoswarm/agent.json`, затем `sudo systemctl restart thermoswarm-agent`.

Агент **сам ничего не делает**: он ждёт команд сервера, а армится только по кнопке «Старт роя».

## 6. Проверки на земле (без пропеллеров)

### 6.1 Позиции по меткам
Поднимите каждый дрон рукой на ~1 м над полем. В его карточке:
- `карта` — возраст позы меньше 0,5 с, зелёный;
- `метки` ≥ 1;
- `xyz` совпадает с местом на поле. Например, над меткой 122 должно быть около `0.00 0.00 1.0`, над меткой 126 — около `3.00 0.00`.

Если оси перепутаны (x и y поменяны местами, знак не тот), значит штатная карта борта не совпадает с файлом сервера. Вернитесь к разделу 3.

### 6.2 Ориентация тепловизора
1. Поставьте T1 носом вдоль оси **+X** поля: от метки 122 к метке 126, красная стрелка на карте интерфейса.
2. Поднесите руку **спереди** от дрона. На живом тепловом кадре в интерфейсе пятно должно быть **сверху**.
3. Поднесите руку **слева** от дрона. Пятно должно быть **слева**.

Если это не так, на сервере исправьте в `config.json` поля `thermal → rotate_deg` (0/90/180/270), `flip_h` и `flip_v`. Затем перезапустите сервер (Ctrl+C, `./start_server.sh`).

### 6.3 Аварийный контур (обязательно до первого полёта)
- На пульте проверьте переключатель режима: при переключении из OFFBOARD в ручной режим агент перестаёт давать команды, а в карточке появится «пульт».
- Проверьте kill switch.
- Проверьте failsafe PX4 при потере OFFBOARD: параметр `COM_OBL_RC_ACT` (рекомендуется Land), например в QGroundControl.
- Проверьте сторож связи, без пропеллеров:
  ```bash
  ssh -t technic-1 'sudo systemctl stop thermoswarm-agent'
  ```
  Карточка T1 перейдёт в «нет связи». В полёте при обрыве связи борт сам зависает через 1,5 с и садится через 6 с. Затем верните агента:
  ```bash
  ssh -t technic-1 'sudo systemctl start thermoswarm-agent'
  ```

## 7. Полёты

### 7.0 Высоты для ёлок 1,6 м (стоят по умолчанию)
| | Высота | Над кронами |
|---|---|---|
| T1, тепловой облёт | 3,0 м | 1,5 м → полоса 1,6 м, 4 галса |
| T2/T3, перелёт | 2,8 м | 1,2 м |
| T2/T3, съёмка | 2,6 м | 1,0 м |
| Высота крон в расчёте координат | 1,5 м | — |

Меняется в «⚙ Параметры». Сервер не даст поставить высоту ближе к кронам, чем 0,8 / 0,6 / 0,4 м. Места взлёта и посадки — **на свободных от ёлок участках** (взлёт вертикальный на 1 м, затем подъём на рабочую высоту). Тепловизор на T1 должен смотреть **строго вниз**: наклон 5° даёт смещение точки около 12 см на 1,5 м высоты над кронами.

### 7.0.1 Ручное управление с карты (калибровка, проверки)
Панель **«Ручное управление»** под картой:
1. Выберите дрон и высоту ползунком, нажмите **«Взлёт»**: дрон взлетает, находит себя по меткам и поднимается на эту высоту.
2. Включите **«клик по карте = лететь»** и кликните точку на карте: дрон летит туда на высоте ползунка. При подъёме он сначала набирает высоту, при снижении — сначала долетает и потом снижается.
3. **«Зависнуть»** — остановиться на месте; **«Сесть»** — посадка выбранного дрона; **«⌂ Домой и посадка»** вверху — все ручные дроны возвращаются на место взлёта и садятся.

Работают все защиты миссии: зазор 0,5 м (точку ближе 1,26 м к другому дрону сервер не примет; два дрона, направленные навстречу, разойдутся), сторож связи, потеря меток, батарея, пульт. Высота — от 0,6 до 4,5 м; **над ёлками выбирайте ≥ 2,2 м**. Пока кто-то летает вручную, «Старт роя» и «⚙ Параметры» недоступны.

Пример калибровки наложения: T1 вручную на 3,0 м над тёплыми предметами на высоте крон → ⚙ → «Калибровка по точкам…».

### 7.0.2 Страница оператора: ручная разметка ёлок и аномалий
Адрес: `http://192.168.1.69:8080/op`. Пароль — `config.json` → `operator.password` (по умолчанию `smena-ego`, **смените**; пустая строка выключает страницу). Пароль не попадает в записи полётов и отчёт.

Что можно делать:
- инструменты «🌲 ёлка здоровая», «🌲 ёлка заражённая», «🔥 аномалия» (с классом, например `heater`): клик по карте — объект появляется;
- «✋ выбор»: кликнуть объект, перетащить; справа — точные X/Y, «Сделать заражённой/здоровой», класс аномалии, «Удалить» (или клавиша Delete).

Как это работает в системе:
- В основном интерфейсе ручные объекты появляются сразу и помечены **«ручн.»** (таблицы, подписи на карте, карточка объекта). В `anomalies.json` и `trees.json` у них `"source": "operator"`, каждое действие — строка «Оператор: …» в журнале.
- Ручные объекты — обычные цели миссии: T2/T3 их фотографируют, YOLO даёт класс. Объект, поставленный до старта, сохраняется при старте миссии.
- Поставленная вручную точка не сдвигается: автоматические наблюдения рядом засчитываются ей. «Заражена/здорова», заданное оператором, автоматическая привязка к тепловым аномалиям не меняет.
- Объект, который прямо сейчас осматривает дрон, нельзя двигать и удалять.

### 7.1 Расстановка
Центры дронов ставьте **не ближе 1,2 м** друг от друга. Рекомендуемые места:

| Дрон | Метка | Координаты |
|---|---|---|
| T1 | 104 | (0; −1,5) |
| T2 | 101 | (−2,25; −1,5) |
| T3 | 107 | (2,25; −1,5) |

Если позиции известны, сервер откажет в старте, когда дроны стоят ближе 1,06 м.

**Точная посадка на свою метку.** Ставьте дрон центром на метку. После взлёта сервер привязывает «дом» к центру ближайшей метки (до 0,35 м; в журнале: «T1: дом — метка 104 …»). Можно задать метку явно: `"home_marker": 104` у дрона в `config.json` → `drones`. Посадка идёт ступенями:
1. перелёт к дому на рабочей высоте;
2. снижение до 0,8 м над меткой;
3. выравнивание по меткам, пока ошибка не станет меньше 6 см в течение 1 с;
4. снижение до 0,45 м (метки ещё видны) и ещё одно выравнивание;
5. команда посадки: последние 0,45 м без меток дают снос всего на несколько сантиметров.

В журнале: «посадка на точку старта …, отклонение N см». Параметры в `config.json` → `landing`.

### 7.1.1 Ёлки: все, заражённые и здоровые
Ёлки находит RGB-камера любого летящего дрона (в основном T1 во время облёта). Сверху крона — тёмное колючее пятно на светлом полу; метки (тёмные квадраты) отсекаются по форме. Каждая ёлка получает номер **E1, E2…** и координаты по триангуляции лучей. **Заражённая** — если на ней подтверждённая тепловая аномалия (нагретые белые отметины), иначе **здоровая**. Здоровые ёлки T2/T3 тоже фотографируют (один снимок сверху; `trees.inspect_healthy`, `trees.healthy_views`). Результат — таблица «Ёлки» и обводка на карте (красная = заражена), итог в журнале: «Ёлок: N — заражённых M (E2, E4), здоровых K».

Для точных координат ёлок агенту нужна модель RGB-камеры: она берётся автоматически из `/main_camera/camera_info` и tf (`base_link → main_camera_optical`). Проверка на борту: `--check` печатает строку `camera model (for tree mapping): 640x480 … mount from tf: yes`. Если там `NO`, сервер использует грубую модель (`rgb_camera.hfov_deg`) и пишет об этом в журнал.

Когда будет обучен YOLO на ёлки (классы с `tree` в имени; заражённые, например, `tree_marked`), положите веса в `models/trees.pt` и поставьте `"trees": {"detector": "yolo"}`.

### 7.2 Первый полёт — только T1
```bash
ssh -t technic-2 'sudo systemctl stop thermoswarm-agent'
ssh -t technic-3 'sudo systemctl stop thermoswarm-agent'
```
1. Поставьте пропеллеры на T1. Пилот с пультом на месте.
2. Нажмите **«Старт роя»**. T1 взлетает на 1 м и ищет метки. Если не нашёл за 15 с — садится сам.
3. Нашёл → поднимается на 2 м и облетает поле галсами. Фото T1 делает сам после облёта: фотодронов нет.
4. Если что-то не так — **«Пауза»** (зависание), **«Домой и посадка»**, **«ПОСАДИТЬ ВСЕХ»** или пульт.

Нюанс взлёта: PX4 должен давать взлёт по `navigate(auto_arm)`, пока камера ещё не видит метки, то есть нужна позиция от оптического потока или метки под камерой на земле. Если T1 не взлетает (в журнале «взлёт отклонён бортом»), поставьте его так, чтобы под камерой была метка, и проверьте источник позиции в PX4.

**Калибровочный полёт:** поставьте кружку с горячей водой на метку 122. После облёта на карте должна быть аномалия около (0; 0). Если она смещена или зеркальна, проверьте п. 6.2 и углы `hfov_deg`/`vfov_deg` (56/42).

### 7.3 Пара: T1 + T2
```bash
ssh -t technic-2 'sudo systemctl start thermoswarm-agent'
```
«Старт роя». T2 ждёт на 1,3 м и облетает каждую находку T1: снимок сверху и 4 ракурса по кругу 0,5 м. На карте видна его «зона осмотра».

### 7.4 Тройка
```bash
ssh -t technic-3 'sudo systemctl start thermoswarm-agent'
```
«Старт роя». Аппараты держат между корпусами зазор не меньше 0,5 м (центры ≥ 1,26 м) и не пролетают друг над другом. Мешающий дрон отходит в сторону.

### 7.5 Во время полёта

| Видите | Значит | Что делать |
|---|---|---|
| «ждёт T1» в карточке | дрон уступает дорогу | ничего |
| «нет меток · зависание» | камера потеряла метки | ничего: вернутся — продолжит, через 10 с сядет сам |
| «задержка связи · зависание» | Wi-Fi тормозит > 1 с | подойти ближе к роутеру / убрать помехи |
| «пульт» | пилот взял управление | пилот сажает сам, остальные продолжают |
| «СТОП: сосед ближе 0.5 м» | сработал сторож на борту | наблюдать; при повторах — «Пауза» |
| аномалия «дрон?» | пятно рядом с дроном, чья позиция недостоверна | проверить глазами, это не находка |

### 7.6 После посадки
- Кнопка **«⤓ Отчёт»** скачивает архив миссии: журнал, телеметрию, все тепловые кадры, фото и аномалии. На сервере он лежит в `~/thermoswarm/runs/<дата-время>/`.
- Перед снятием АКБ остановите агентов: `ssh -t technic-N 'sudo systemctl stop thermoswarm-agent'`. При следующем включении борта агент стартует сам.

## 8. Типовые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| `error: externally-managed-environment` | Ubuntu 24.04 запрещает pip вне окружения | `./start_server.sh` (сам создаёт `.venv`) |
| В карточке «нет связи» | агент не запущен / неверный IP / ufw | `ssh technic-N systemctl status thermoswarm-agent`; IP сервера в `~/thermoswarm/agent.json` на борту; `sudo ufw allow 7700/tcp` |
| `another agent is already running` | агент уже запущен службой | для ручных проверок: `sudo systemctl stop thermoswarm-agent` |
| «метки не видны 15 с на 1.0 м … поднимаюсь до 1.6 м», затем «метки не найдены (… маркеров в кадре: N …) — посадка» | камера не видит поле, другая карта/словарь, свет. Сервер сам делает вторую попытку выше (`flight.search_alt_m`) | смотрите число маркеров в сообщении: 0 — камера/карта (раздел 3, п. 6.1), 1–2 — поставьте дрон дальше от края поля или поднимите `takeoff_alt_m` |
| «борт отклонил взлёт: «…» — повтор через 4 с» | PX4 ещё не готов сразу после включения (EKF не сошёлся, проверки арминга) | ничего: сервер повторит до 2 раз (`flight.takeoff_retries`); если отказ окончательный — текст PX4 в сообщении, смотрите QGroundControl |
| «без меток оценка высоты ушла на +X м … посадка сейчас» или дрон «сам сел» посреди полёта | высота PX4 берётся из камеры по меткам; без меток оценка уплывает (до 0,5 м/с), удерживая «высоту», дрон на деле снижается | на борту в QGroundControl проверить источник высоты: `EKF2_HGT_REF` (PX4 ≥ 1.14) или `EKF2_HGT_MODE` (старые): 3 = Vision. Если на «Технике» есть дальномер — поставить 2 (Range) и `EKF2_RNG_CTRL` = 1; иначе 0 (Baro). Метки теряются над кронами: высоты осмотра уже подняты (2,6 / 2,8 м) |
| «Детектор ёлок выключен: No module named 'cv2'» | на ноутбуке нет OpenCV | перезапустить `./start_server.sh` (доставит пакеты) или `.venv/bin/pip install opencv-python-headless` |
| «борт не прислал геометрию RGB-камеры (старый агент?)» | на борту agent-1.0 | `./tools/deploy_board.sh …` для каждого борта (раздел 5) |
| «Тепло за краем поля: A… — не осматривается» | нагреватели/люди за пределами поля | так и задумано; на карте статус «вне поля» |
| Дроны на земле «уезжают» по карте | на земле камера не видит меток (слишком близко), PX4 интегрирует optical flow и позиция плывёт | сервер это учитывает: разоружённый дрон показывается и обходится в последней точке, где он видел метки. На борту на позицию до взлёта не полагайтесь — после отрыва метки снова в кадре и позиция поправляется (без ложной тревоги «скачок»)|
| «команда goto не выполнена: Can't transform from aruco_map» | нет позы по меткам | дрон висит сам; проверить высоту и метки |
| «взлёт отклонён бортом» | PX4 запретил арминг (preflight) | сообщения PX4 в QGroundControl |
| «Старт отклонён: стоят слишком близко» | центры ближе 1,06 м | раздвинуть |
| «нет тепловых кадров» | TR256i отвалился | кабель, `--probe-thermal` (раздел 5) |
| «нет кадров с камеры — осмотры ему не назначаются» | RGB-камера дрона | `rostopic hz /main_camera/image_raw` на борту |
| Нет видео в плитке при подключённом дроне | топик камеры другой | `camera_topic` в `agent.json` на борту |

## 9. Обновление ПО

- **Сервер:** Ctrl+C, распаковать новый архив поверх `~`, `./start_server.sh`.
- **Борта:** повторить команды раздела 5. Агент переустановится, `agent.json` перезапишется.
- **Параметры полёта из интерфейса:** кнопка **«⚙ Параметры»**. Там ползунки: высота и скорость теплового облёта, перекрытие галсов, порог нагрева, высота целей, высоты перелёта и съёмки T2/T3, число ракурсов и радиус облёта цели, пауза перед снимком, скорость T2/T3, высота взлёта, зазор между корпусами (не меньше 0,5 м), напряжение посадки.
  - Менять можно только между миссиями. Изменения действуют со следующего «Старт роя» и сохраняются в `config.json`.
  - Внизу окна сразу видно, сколько получится галсов и какой у них шаг.
- **Остальные настройки** (поле зрения и ориентация тепловизора, границы поля, тайм-ауты): правятся в `~/thermoswarm/config.json` на сервере, затем перезапуск сервера. Описание всех полей — `docs/CONFIG.md`.
- **Наложение тепла на RGB:** в плитке «T1 · RGB» галочка «тепло» и кнопка ⚙ (прозрачность, «нагрев от», масштаб, сдвиг, поворот, зеркально). Только для отображения: на поиск аномалий не влияет.
- **Калибровка наложения по точкам:** ⚙ → «Калибровка по точкам…».
  1. Под T1 положите 4–6 тёплых предметов по разным углам кадра (кружки с горячей водой, ладони). Дрон и предметы неподвижны.
  2. «Новые кадры» — оба кадра замораживаются.
  3. Для каждого предмета кликните точку на тепловом кадре слева, затем ту же точку на RGB справа.
  4. «Подобрать» — программа сама находит масштаб, поворот, сдвиг и зеркальность и показывает среднюю ошибку в пикселях; хорошо, если меньше 10.
  5. «Перетаскивание» — ручная доводка: мышь двигает изображение, колесо меняет масштаб, Shift + колесо поворачивает.
  6. «Применить» — настройки сохраняются в этом браузере.

# ThermoSwarm v15 — установка и запуск

Сервер: ноутбук `192.168.1.69`. Борта: `technic-1` (T1, тепловизор TR256i), `technic-2` (T2), T3.

## 1. Сервер (ноутбук)
```bash
# остановить старый сервер: Ctrl+C в его окне
cd ~
unzip -o thermoswarm_2026-11-11_v15.zip
cd thermoswarm
nano config.json          # "operator": {"password": "…"} — поставьте свой пароль
./start_server.sh
```
`config.json` из архива перезаписывает ваш: если меняли в нём что-то руками (кроме «⚙ Параметры»), перенесите.
Интерфейс: `http://192.168.1.69:8080`. Страница оператора: `http://192.168.1.69:8080/op`.

## 2. Агенты на борта (нужен agent-1.1; если уже ставили v13/v14 — можно пропустить)
```bash
cd ~/thermoswarm
./tools/deploy_board.sh T1 technic-1 192.168.1.69 tr256i
./tools/deploy_board.sh T2 technic-2 192.168.1.69
./tools/deploy_board.sh T3 <ssh-адрес-T3> 192.168.1.69
```
В выводе проверки каждого борта должно быть:
- `markers visible: N` (N > 0, если дрон над полем);
- `camera model (for tree mapping): … mount from tf: yes` — модель камеры для координат ёлок.
Если `NO` — всё работает, но координаты ёлок грубее; пришлите вывод.

## 3. Расстановка
- Каждый дрон — **центром на свою метку**: T1 → 104, T2 → 101, T3 → 107 (или любые свободные от ёлок метки, центры не ближе 1,2 м).
- После взлёта в журнале: «T1: дом — метка 104 …». Посадка — на эту же метку, в журнале «отклонение N см».
- Закрепить метку за дроном жёстко: `config.json` → `drones` → `"home_marker": 104`.
- Тумблер режима на пульте — **Stabilized** (перехват — переключением тумблера).

## 4. Полёт
1. Первый раз — только T1 в ручном режиме (панель под картой): «Взлёт» → клики по карте → «⌂ Домой и посадка». Проверить точность посадки.
2. Миссия: «▶ Старт роя».
   - T1 облетает поле: тепловые аномалии A…, ёлки E… (RGB).
   - Ёлка с подтверждённым теплом — **заражена**, остальные — **здоровы**.
   - T2/T3: аномалии — 5 ракурсов, здоровые ёлки — 1 снимок сверху.
   - В конце: «Ёлок: N — заражённых M (…), здоровых K», все садятся на свои метки.
3. «⤓ Отчёт» — архив записи (фото, аномалии, ёлки, журнал).

Если не взлетает: сервер сам повторит взлёт до 2 раз; если меток не видно на 1 м — поднимется до 1,6 м. Окончательная ошибка содержит число меток в кадре: 0 — камера/карта, 1–2 — край поля.

## 5. Страница оператора `/op`
- Вход по паролю из `config.json`.
- 🌲 «ёлка здоровая», 🌲 «ёлка заражённая», 🔥 «аномалия» (класс, например `heater`) → клик по карте.
- ✋ «выбор» → клик по объекту, перетащить; справа — X/Y, «заражена/здорова», класс, «Удалить» (или Delete).
- В основном интерфейсе такие объекты сразу видны с пометкой **«ручн.»**, в журнале — «Оператор: …», в отчёте — `"source": "operator"`.
- Ручные объекты — обычные цели: дроны их фотографируют. Поставленные до старта — сохраняются.
- Объект, который сейчас осматривает дрон, нельзя двигать/удалять.

## 6. Нагреватели других команд
Тепловизор находит их как аномалии — это правильно. Чтобы они не «заражали» ёлки рядом:
- с обученной YOLO (класс `heater`) — автоматически;
- без неё — на странице оператора задать аномалии класс `heater`.
Ёлка заражается только аномалией ближе 0,5 м к её центру.

## 7. YOLO (когда будет время)
Пошагово: `docs/YOLO_TREES.md` — классы `tree`, `tree_infected`, `heater`, съёмка, разметка, обучение, подключение (`models/rgb.pt`). Без YOLO всё работает, в колонке «объект» будет «не распознан».

## 8. Если что-то не так — прислать
- скрин карты + «⤓ Отчёт»;
- ёлки не находятся / лишние: 2–3 кадра T1 с высоты 3 м (📷 в карточке T1, файлы в `dataset/raw/`);
- посадка неточная: строку «отклонение … см» и насколько реально промахнулся.

Подробно: `LAUNCH.md` (7.0.2 — страница оператора, 7.1 — посадка, 7.1.1 — ёлки, 8 — типовые проблемы).
